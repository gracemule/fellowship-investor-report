# Deployment hand-off

Prompt for the agent that deploys this repository (it needs access to Render and GitHub).
The repository is complete and tested; the job is the web deployment only.

---

You are deploying `https://github.com/gracemule/fellowship-investor-report` to Render. Read `README.md`,
`Dockerfile`, `render.yaml` and `.env.example` first. The application is finished; change application code only
to fix something that blocks deployment, and put any such change on a branch with a pull request rather than on
`main`.

**What it is.** A FastAPI app (`python -m chui_reporter.app`) that runs a LangGraph agent as a background
worker thread inside the same process. Users sign in with a shared password, point it at a local folder of fund
documents, and the agent builds an investor report (Word and PDF), shown page by page in the browser. State lives in
Neon Postgres, which already exists.

**Deploy it as one Render web service, built from the `Dockerfile`** (`render.yaml` is a ready Blueprint).

* Exactly **one instance** (`numInstances: 1`). A run is owned by the process that started it and crash recovery
  assumes a single owner. Do not enable autoscaling.
* Plan **Standard (2 GB) or larger**. LibreOffice conversion and PDF rasterising run out of memory on 512 MB tiers.
  Not a free instance: free services sleep, and sleeping kills the agent mid-run.
* **Region:** the same as the Neon database (visible in its connection string host), to keep database latency low.
* Health check path `/healthz`.
* No persistent disk is needed; the database is the source of truth and the working folder is rebuilt per run.

**Environment variables.** Set them in the Render dashboard. Ask the user to enter the secret values there
themselves; never request them in chat, never put them in the repository or in `render.yaml`.

| Variable | Notes |
| --- | --- |
| `DATABASE_URL` | Neon **pooled** connection string. **The previous Neon password was exposed once in a development session: have the user rotate it in Neon first, then use the new string.** |
| `CHUI_ACCESS_PASSWORD` | Required. The shared sign-in password. The app refuses to start without it. |
| `DEEPSEEK_API_KEY` | Primary provider. |
| `ANTHROPIC_API_KEY` | Optional; enables the Anthropic provider and automatic fallback. |
| `CHUI_PROVIDER` | `deepseek` (default). |
| `CHUI_FALLBACK_PROVIDER` | `anthropic`, used only if its key is set. |
| `CHUI_SESSION_SECRET` | Generated by the Blueprint. |
| `CHUI_ENV` | `production`. **Never `dev`** (it disables the password). |

**Do not** set `CHUI_SOURCE_ROOT` or `CHUI_WORKDIR`; the image sets the working directory.

**Things that will not be in the image, by design**

* The brand fonts (Larken) are licensed and are not in the repository. They are installed at run time from the
  `Branding` folder the user syncs from their computer (`src/chui_reporter/render/fonts.py`). A run fails with a clear
  message if they are missing. Do not try to bake them into the image or commit them.
* The web interface also serves the brand fonts to the signed-in browser from the synced `Branding` folder
  (`@font-face` in `app.css`, route `/brand/...`). Ask the user to confirm their font licence covers web use; if
  not, delete those `@font-face` rules and the interface falls back to system fonts.
* No fund documents are in the repository, and none may be added. The repository is public.

**Verify, in this order, and report each result**

1. The image builds. If the LibreOffice package set is wrong for Debian bookworm, fix it. Confirm `soffice --version`
   works inside the container as the non-root user.
2. `/healthz` returns 200; the root page shows the sign-in screen; the wrong password is refused; the right one signs in.
3. In Chrome, choose a folder: files sync, the Sources tab fills in, and (when the required documents are present)
   a run starts and the activity feed narrates it. This needs real fund documents, so ask the user to do this step
   with you. Confirm the rendered report appears on the right and both downloads work.
4. Redeploy or restart the service while a run is in progress. Within about two minutes the run should be picked up
   and continue (the feed shows "The server restarted mid-run").
5. Server-sent events (`/api/events`) stay open through Render's proxy. If they are buffered or cut, fix the
   configuration, not the application.
6. Look at the logs for errors on a full run and fix deployment-level causes.

**Security reminders.** Keep the service behind the password; do not add a public route that exposes data. Confirm with
the user whether the GitHub repository should be made private: it is public now, and although it holds code only, the
extraction code names the fund's LPs and portfolio companies.

When done, reply with the service URL, the instance size and region, and anything you could not verify or that needs the
user's attention.
